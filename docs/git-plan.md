# Suggested Incremental Git Commit History

Use these as the commit boundaries while developing. The point is to show coherent evolution rather than one giant final commit.

1. `docs: define product scope and architecture`
2. `chore: initialize FastAPI backend and database configuration`
3. `feat: add employee model, migrations, and seed data`
4. `feat: add employee CRUD and filtering APIs`
5. `test: cover employee validation and API behavior`
6. `feat: add salary analytics service and endpoint`
7. `feat: build React employee management UI`
8. `feat: add salary analytics dashboard`
9. `test: add end-to-end salary update workflow`
10. `docs: add setup, trade-offs, AI notes, and deployment guidance`
11. `chore: prepare production deployment configuration`

Before final submission, the candidate should make these commits under their own Git identity and push the repository to the requested Git hosting provider.
